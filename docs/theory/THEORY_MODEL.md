# SymAFL 路径约束二叉树的适用条件与理论基础

_本文建立受控测试场景的模型，区分理想的完整路径约束二叉树与 SymAFL 当前的增量 PCBT 实现，并说明二叉性、成立前提及真实软件中的适用边界。_

---

## 🧩 交互事件与交互确定性程序

### 外部执行环境交互事件

设程序 \(P\) 在一次执行中与外部执行环境发生的、可能影响程序状态或控制流的交互事件构成序列：

\[
\mathcal{E}=\langle e_0,e_1,\ldots,e_n\rangle.
\]

交互事件是一个**语义边界**，而不是系统调用或中断的同义词。只要某个结果不是由程序当前内部状态唯一决定、却可能影响后续执行，就应视为环境提供的事件。例如：

- 输入接口读取的数据，以及文件、网络、IPC 和系统调用的返回结果
- 时间、随机数、CPU 特性、动态加载结果、地址布局和分配器行为
- 信号、异常、线程调度及其他异步控制流影响
共享状态或外部服务所提供的响应

给定初始程序状态 \(s_0\)，程序执行得到的动态基本块轨迹记为：

\[
B(P,s_0,\mathcal{E})=\langle b_0,b_1,\ldots,b_m\rangle.
\]

### 交互确定性程序

> **定义 1：交互确定性程序**  
> 对任意固定的初始状态 \(s_0\) 和外部交互事件序列 \(\mathcal{E}\)，若程序 \(P\) 的动态基本块轨迹唯一确定，则称 \(P\) 为交互确定性程序。

即任意两次以相同 \(s_0\) 和 \(\mathcal{E}\) 进行的执行均满足：

\[
B^{r_1}(P,s_0,\mathcal{E})=B^{r_2}(P,s_0,\mathcal{E}).
\]

该定义不要求程序是纯函数，也不要求程序不读取文件、不访问网络或不使用线程。它只要求：一旦初始状态和所有会影响执行的交互反馈都被固定，程序自身不再产生额外的控制流不确定性。

因此，若线程调度、异步信号或未定义行为会改变轨迹，它们必须被纳入 \(\mathcal{E}\) 并固定或重放；否则该执行场景不满足交互确定性。

## 🎛️ 受控确定性测试环境

设测试环境为 \(T\)，fuzzer 给出的 test case 为 \(x\)。环境依据配置向程序提供交互事件序列：

\[
\mathcal{E}_T(x)=\langle e_0(x),e_1(x),\ldots,e_n(x)\rangle.
\]

> **定义 2：受控确定性测试环境**  
> 若对于固定环境配置和固定 test case \(x\)，测试环境总能向程序重放相同的交互事件序列 \(\mathcal{E}_T(x)\)，则称 \(T\) 为受控确定性测试环境。

即：

\[
\forall x,\quad
\mathcal{E}^{r_1}_T(x)=\mathcal{E}^{r_2}_T(x).
\]

测试环境可将交互反馈划分为固定部分和可变部分：

\[
\mathcal{E}_T(x)=\mathcal{E}_{\mathrm{fix}}\cup\mathcal{E}_{\mathrm{var}}(x).
\]

其中 \(\mathcal{E}_{\mathrm{fix}}\) 由环境固定或 record/replay，\(\mathcal{E}_{\mathrm{var}}(x)\) 由 test case \(x\) 决定。例如，将标准输入接入 AFL++ 时：

\[
\mathcal{E}_{\mathrm{var}}(x)=\operatorname{read}(\texttt{stdin})\mapsto x.
\]

`hook + record/replay`、系统调用拦截、虚拟时间、确定性随机数、mock 外部服务、确定性调度，以及每轮重置进程和持久状态，都是构造此类环境的可选技术。环境不要求所有反馈都是常量；它可以有状态，只要相同配置和相同 \(x\) 总能得到相同的事件序列。

> 📌 **当前实现边界：** “所有可变反馈均可符号化”是下文的理论前提，不是当前 SymAFL runtime 自动提供的能力。现有 QSYM 集成默认将 stdin（fd 0）读取的字节创建为符号输入；其他文件、网络、时间或调度反馈不会自动变成符号变量。除非 harness 将它们编码进 stdin，或另行扩展 wrapper/runtime，它们必须被固定、重置或重放。

## ✅ SymAFL 的适用测试场景

> **定义 3：SymAFL 适用测试场景**  
> 一个测试场景是 SymAFL 的适用场景，当且仅当它同时满足以下条件。

1. **目标程序交互确定**：在测试使用的初始状态和交互事件模型下，目标是交互确定性程序。
2. **测试环境受控且可重放**：固定环境配置和 test case 后，环境提供的交互事件序列唯一确定。
3. **所有可变交互反馈均被符号化**：对每一项随 \(x\) 变化的环境反馈，都存在稳定的符号表示；若以输入字节为例，

   \[
   \mathcal{E}_{\mathrm{var}}(x)\longleftrightarrow X=\{X_0,X_1,\ldots,X_{n-1}\},
   \]

   其中 \(x\) 是符号变量 \(X\) 的一个具体赋值。
4. **符号状态与记录规则完备且稳定**：从可变反馈产生的符号数据，经过算术、内存、类型转换、调用与返回等传播后，凡是影响路径选择的依赖都被正确保留；路径谓词的构造、规范化和记录顺序在可比较的运行之间保持一致。
5. **前缀状态可判定**：若两次执行具有相同的、已记录的路径谓词前缀及相同的路径结果前缀，则它们处于同一符号执行状态；下一条路径谓词的身份和后继符号状态仅由该前缀及其下一次 true/false 结果决定。

第 5 项是“完整符号跟踪”在建树语境中的关键展开。仅有“固定 test case 的轨迹可重放”还不够：不同 test case 即使暂时满足相同的路径结果，也可能在下一处遇到不同的谓词。只有符号状态完整且规范化稳定时，已共享的路径前缀才能代表同一个抽象执行状态，并安全地复用一个树节点。

### 理想路径决策事件

为陈述路径约束二叉树的理论结论，先定义理想模型中的**路径决策事件**：

\[
d_i=(q_i,\phi_i,\beta_i),\qquad \beta_i\in\{\mathsf{T},\mathsf{F}\}.
\]

其中 \(q_i\) 是当前符号执行状态，\(\phi_i\) 是该状态下的下一条规范化布尔路径谓词，\(\beta_i\) 是其实际结果。相应的路径文字为 \(\ell_i=\phi_i\)（\(\beta_i=\mathsf{T}\)）或 \(\ell_i=\lnot\phi_i\)（\(\beta_i=\mathsf{F}\)）。

在定义 3 的条件下，固定 \(x\) 的完整理想路径决策序列唯一且可重放：

\[
D(P,T,x)=\langle d_0,d_1,\ldots,d_{k-1}\rangle,
\qquad
D^{r_1}(P,T,x)=D^{r_2}(P,T,x).
\]

这里的 \(D\) 是理论对象：它记录所有纳入模型的路径选择。它不等同于基本块轨迹 \(B\)，也不等同于当前 QSYM 实际持久化的 solver assertion 序列。

## 🌳 理想的完整路径约束二叉树

### 定义

令 \(\epsilon\) 表示空路径前缀。对一个已观测 test case 集合 \(S\)，定义理想的完整路径约束二叉树 \(T_{\mathrm{full}}(S)\) 如下：

1. 树有一个虚拟根 \(\epsilon\)，代表尚未发生任何路径决策
2. 对每个 \(x\in S\)，从 \(\epsilon\) 开始，将其完整决策序列 \(D(P,T,x)\) 逐项融入树
3. 一个节点代表一个已共享的决策前缀，也就是一个由该前缀唯一确定的符号执行状态
4. 在节点的下一谓词 \(\phi\) 上，按实际结果 \(\mathsf{T}\) 或 \(\mathsf{F}\) 进入相应后继状态

因此，\(T_{\mathrm{full}}(S)\) 是已观测完整理想决策序列的前缀闭包。它不是静态 CFG，不是 AFL coverage bitmap，也不是“所有可能程序路径”的枚举；它只表示当前已观测集合在理想符号执行状态空间中的路径前缀关系。

### 定理：完整路径约束二叉树的二叉性

> **定理 1：二叉性**  
> 在 SymAFL 适用测试场景中，理想的完整路径约束二叉树 \(T_{\mathrm{full}}(S)\) 是一棵二叉树：任意节点至多有一个 true 子树和一个 false 子树。

**证明。** 固定任一节点 \(v\)。根据定义，\(v\) 对应一个已共享的路径前缀；由定义 3 的前缀状态可判定性，它唯一确定当前符号执行状态 \(q\) 及下一条布尔谓词 \(\phi\)。\(\phi\) 的结果域为 \(\{\mathsf{T},\mathsf{F}\}\)。

对任一固定结果 \(\beta\in\{\mathsf{T},\mathsf{F}\}\)，前缀状态可判定性又保证 \((q,\phi,\beta)\) 唯一确定其后继符号状态。因此，在 \(v\) 处不可能出现两棵不同的、都标记为 \(\beta\) 的子树；否则它们会对应同一前缀状态、同一谓词和同一结果，却有不同后继状态，矛盾。故 \(v\) 至多有一个 true 子树和一个 false 子树，\(T_{\mathrm{full}}(S)\) 为二叉树。证毕。

这里应严格区分两种二分：

- **数据来源二分**：一个路径谓词可能只含固定 concrete 值，也可能依赖被跟踪的符号值
- **树结构二分**：每个理想路径谓词只能求值为 true 或 false

定理 1 只依赖第二种二分，以及共享前缀可唯一确定符号状态的条件；“concrete 或 symbolic”不是二叉性的证明理由。

### 多路控制转移的处理

源级或 LLVM 层的控制转移不一定天然二叉。例如，`switch` 是多路选择。定理 1 的二叉性是对**规范化布尔路径谓词**而言的：多路选择必须在理论模型中展开为有序的一系列布尔 case-equality 谓词；每一个 equality 事件仍只有 true/false 两个结果。默认分支由这些 equality 的 false 结果序列表示，而不是成为某个节点的第三个孩子。

同样，间接跳转、异常传播、异步信号或其他控制机制，只有在被纳入理想路径决策事件、且满足定义 3 的状态与记录条件时才能适用定理 1。否则，它们必须被环境固定或 record/replay；不能将定理直接外推到这些机制。

## ⚙️ 当前 PCBT：理论树的受限前缀优化

### 记录 assertion 序列与理想决策序列的差异

当前 SymAFL 实际向 PCBT 持久化的不是 \(D\)，而是 QSYM solver 的 assertion 序列：

\[
A(P,T,x)=\langle a_0,a_1,\ldots,a_{r-1}\rangle.
\]

它是对理想决策序列的实现相关投影，而不是逐项等同的日志：只含 concrete 值的条件可被省略；solver 可对 assertion 去重；除条件分支外，`select`、`switch` case equality，以及符号地址或间接调用的 concrete-consistency assertion 也可能进入该序列。因此，\(A\) 中的每一个元素都可作为 PCBT 进行 SAT 检查的布尔 assertion，但并非每一个元素都等同于一个源级控制转移。

由此，当前 PCBT 的物理二叉结构——每个 `PathConNode` 只有 `left` 和 `right` 两个子槽位——是一个实现不变式。若要将该结构解释为理想二叉树的正确压缩，还必须额外满足下述 assertion 对齐契约。

### 增量插入协议

理想模型会保存完整 \(D(P,T,x)\)，再从虚拟根 \(\epsilon\) 开始合并。当前 SymAFL 用 `CheckInput()`、`insert_depth` 和 `InsertTrace()` 避免每次保存已共享的前缀：

1. `CheckInput()` 将候选输入字节代入当前 PCBT 节点的 assertion，SAT 时沿 `left` 前进
2. 当某节点 assertion 对候选输入不可满足且该节点尚无 `right` 子节点时，它选择该节点，并返回 `node.depth + 1`
3. AFL++ 将该返回值写入共享内存作为 `insert_depth`
4. runtime 以该数值为当前 `solver.assertions()` 数组的切片起点，只持久化后缀
5. `InsertTrace()` 将后缀首个 assertion 接入所选节点的 `right` 子节点，再将余项串接为 `left` 链

工程实现并不比较候选完整 trace 与树中 assertion 的身份，也不验证后缀首项一定是父 assertion 的逻辑否定。因此，它不是对任意完整 assertion 序列的通用 trie 合并算法；“首次偏离已知前缀”是只有在以下**assertion 对齐契约**成立时才具有的语义解释。

### assertion 对齐契约与条件性结论

> **对齐契约**  
> 对被 `CheckInput()` 选中的候选输入，预检和其后的 symbolic execution 必须使用相同初始状态、受控环境、插桩/运行时配置和 solver 记录规则；并且：
>
> 1. PCBT 的既存节点链与该次 `solver.assertions()` 的已共享前缀逐项同序、同义
> 2. `node.depth + 1` 恰为当前 assertion 序列中首个应持久化位置
> 3. 后缀首项属于所选节点的 false/right continuation，余项顺序与 runtime assertion 顺序一致
> 4. 候选不会在已有 `left` 链叶节点之后产生尚未表示、却需要插入的新 continuation

> **定理 2：增量 PCBT 的条件性前缀保持**  
> 若对齐契约成立，则 `CheckInput()` 所选节点和 `insert_depth` 可正确表示共享 assertion 前缀后的插入位置；`InsertTrace()` 写入的后缀保持该前缀关系，并保持每个节点至多一个 `left`、一个 `right` 子节点的物理二叉不变式。

这一定理将当前实现描述为建立在理想树性质之上的**受限前缀优化**：它只对已保留、已插入的 assertion trace 作条件性结论，不声称已枚举全部可达基本块路径、全部程序状态或全部未记录控制转移。

实现对应关系见 [PathConTree.cpp](AFLplusplus/src/PathConTree.cpp) 中的 `CheckInput()` 和 `InsertTrace()`，以及 [Runtime.cpp](symcc/runtime/src/backends/qsym/Runtime.cpp) 中由共享 `insert_depth` 控制的 trace 持久化。

### 深度的准确含义

在当前实现中，`insert_depth` 首先是“所选 PCBT 节点深度加一”，随后被 runtime 当作 `solver.assertions()` 数组的切片起点。它**只有在 assertion 对齐契约成立时**，才能解释为该次 solver assertion 序列中首个新断言的下标。

因此，它不是源码分支数量、完整动态控制转移数量、基本块深度或完整 CFG 路径长度；并且在实现未校验 assertion 对齐的情况下，也不应将它无条件称为语义上已验证的 assertion 下标。

## 🧪 交互确定性在真实软件中的普遍性与边界

交互确定性不是某个二进制固有、永久不变的标签；它是**目标程序、harness、初始状态和环境控制策略共同形成的测试场景属性**。

从语义上看，这一性质相当普遍：许多顺序程序在全部影响执行的输入和事件都被固定后，本来就具有确定行为。困难不在于“程序是否理论上可以确定”，而在于 fuzzing 场景能否识别、控制并重放足够完整的交互事件。

| 目标类别 | 在受控 fuzzing 中的典型状态 | 主要环境控制工作 |
| --- | --- | --- |
| 文件/stdin 解析器、解码器、格式转换器、批处理 CLI | 通常较容易满足 | 固定文件系统依赖、每轮重启或 fork，符号化主输入 |
| 可重置的库 API harness、单请求协议解码器 | 通常较容易满足 | 固定 API 初始状态、将请求编码为 test case、mock 回调 |
| 多阶段协议或长连接服务 | 默认较难满足 | 将会话输入、服务端响应和连接状态纳入 test case 或 record/replay |
| 依赖数据库、缓存、文件系统写入或远端服务的应用 | 默认较难满足 | 快照/重置状态、虚拟化依赖或记录外部响应 |
| 时间/随机数敏感、并发、异步信号或硬件时序敏感程序 | 默认较难满足 | 虚拟时间、确定性随机源、调度控制、事件重放或扩大记录域 |

因此，交互确定性在受控 fuzzing 工作负载中是常见且可工程化获得的性质，特别适合输入驱动的解析与批处理目标；但它并非部署环境中所有真实软件天然满足的事实。对于复杂服务或并发系统，若无法冻结、重置、模拟或重放影响路径的交互，PCBT 应只被视为启发式筛选，而不应套用本文的语义正确性结论。

## 📝 结论

SymAFL 的理论基础可以概括为：将所有影响执行的外部因素抽象为交互事件；在交互确定的目标与受控可重放的环境中，将所有可变反馈符号化，并以稳定、完备的符号状态和路径记录规则表示路径选择。固定 test case 因而对应唯一且可重放的理想路径决策序列。

若每次都保存完整理想决策序列并从虚拟根合并，则在“共享前缀唯一确定符号状态”的条件下，路径约束二叉树必然二叉：每个规范化布尔路径谓词至多有一个 true 子树和一个 false 子树。当前 SymAFL PCBT 的 `CheckInput()`、`insert_depth` 与增量 `InsertTrace()` 不是二叉性的假设，而是利用稳定前缀来减少重复 trace 保存和合并的工程优化；由于当前实现实际处理的是受过滤、可能去重的 solver assertion 序列，其语义正确性还取决于跨组件的 assertion 对齐契约。
